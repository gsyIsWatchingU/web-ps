# 坐标偏移问题修复计划

## 问题概述
用户反馈三个坐标偏移问题：
1. 裁剪时红框相比图片偏左上
2. 涂鸦时鼠标松开后涂鸦内容突然向右下移
3. 局部重绘时画笔落笔区域相较于图片偏左上

## 当前状态分析

### 1. 裁剪预览问题
**文件**: `src/features/editor/runtime/seedCanvas.ts`

**问题代码** (createImageObject 函数，第 133-143 行):
```javascript
if (previewingCurrentLayer) {
  image.set({
    cropX: 0,  // 错误：应该使用 layer.crop.x
    cropY: 0,  // 错误：应该使用 layer.crop.y
    width: layer.originalWidth,
    height: layer.originalHeight,
    left: layer.transform.x - layer.crop.x * layer.transform.scaleX,
    top: layer.transform.y - layer.crop.y * layer.transform.scaleY
  });
}
```

**根本原因**: 裁剪预览时设置 `cropX=0, cropY=0` 意味着从图片原点开始显示整个图片，但 `left/top` 的计算却减去了 `crop.x * scaleX`。而 `drawCropOverlay` 中计算裁剪框位置使用 `layer.transform.x + crop.x * scaleX`（加法），两者计算方式相反，导致预览图片位置和裁剪框不匹配。

### 2. 涂鸦坐标偏移问题
**文件**: `src/features/editor/store/useEditorStore.ts`

**问题代码** (createDoodleLayer 函数，第 504-519 行):
```javascript
transform: {
  x: Math.round(minX),  // transform 是文档坐标
  y: Math.round(minY),
  ...
},
points: points.map((point) => ({
  x: point.x - minX,  // points 是相对坐标
  y: point.y - minY
})),
```

**根本原因**: 在 `seedCanvas.ts` 的 `applyCommonProps` 中，Fabric.js 的 Polyline 对象被设置 `left = layer.transform.x, top = layer.transform.y`。但 Polyline 的 `points` 已经是相对坐标（经过 minX/minY 转换），而 `left/top` 是文档坐标（minX, minY）。这导致 Polyline 实际位置是 `transform.x + point_relative`，而不是预期的 `transform.x + point_relative = 文档坐标点`。

### 3. 局部重绘描边偏移问题
**文件**: `src/features/editor/runtime/imageEditBridge.ts`

**问题代码** (mapStrokePointToCrop 函数，第 214-224 行):
```javascript
function mapStrokePointToCrop(layer: ImageLayer, point: RepairStroke["points"][number]) {
  const scaleX = layer.transform.scaleX || 1;
  const scaleY = layer.transform.scaleY || 1;
  const imageX = (point.x - layer.transform.x) / scaleX + layer.crop.x;
  const imageY = (point.y - layer.transform.y) / scaleY + layer.crop.y;

  return {
    x: imageX - layer.crop.x,  // 减去了 crop.x，但 imageX 已经加过 crop.x
    y: imageY - layer.crop.y
  };
}
```

**根本原因**: `imageX` 已经通过 `+ layer.crop.x` 计算了裁剪偏移，但返回值又减去了 `layer.crop.x`，导致返回值仍然是 `(point.x - layer.transform.x) / scaleX`，这是相对于图片左上角在文档中的偏移，而不是相对于裁剪区域左上角的偏移。

## 修复方案

### 修复 1: seedCanvas.ts - createImageObject 裁剪预览
**文件**: `src/features/editor/runtime/seedCanvas.ts`

在第 133-143 行，修改为：
```javascript
if (previewingCurrentLayer) {
  image.set({
    cropX: layer.crop.x,
    cropY: layer.crop.y,
    width: layer.crop.width,
    height: layer.crop.height,
    left: layer.transform.x,
    top: layer.transform.y
  });
}
```

这样裁剪预览的图片会正确显示裁剪区域，位置与 `drawCropOverlay` 计算的裁剪框一致。

### 修复 2: useEditorStore.ts - createDoodleLayer 坐标系统
**文件**: `src/features/editor/store/useEditorStore.ts`

在第 504-519 行，修改 transform 的设置，改为存储相对坐标起始点 (0, 0)：
```javascript
transform: {
  x: 0,
  y: 0,
  ...
},
points: points.map((point) => ({
  x: point.x - minX,
  y: point.y - minY
})),
```

同时在 `applyCommonProps` 中，对于 doodle 类型图层，需要特殊处理，确保 Polyline 的 left/top 设为 (minX, minY)。

或者更简洁的方案是：在 `createDoodleObject` 中设置 `left = minX, top = minY`，让点的相对坐标和 Polyline 位置匹配。

### 修复 3: imageEditBridge.ts - mapStrokePointToCrop 坐标转换
**文件**: `src/features/editor/runtime/imageEditBridge.ts`

修改第 220-223 行的返回值：
```javascript
return {
  x: imageX,  // 已经是相对于裁剪区域的坐标
  y: imageY
};
```
