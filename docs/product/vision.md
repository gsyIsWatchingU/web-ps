# Web 修图项目产品愿景

## 项目介绍

Web 端修图面向抖音电商 AIGC 带货图文生成后的二次精修场景。当商家、达人或运营对 AI 生成图片的局部细节、营销表达、视觉风格或平台适配效果不满意时，可以在网页端快速完成轻量编辑，降低反复生成成本，提升图文素材的可用率与投放效率。

从用户角度看，它不是专业设计软件，而是一个电商场景下的轻量化修图工作台：上手快、改得准、出图快。

从平台角度看，它要把工具能力从“只会生成”升级为“生成 + 编辑 + 导出”的闭环，并为后续模板化、自动化、智能推荐打基础。

## 用户价值

用户生成带货图后，常见痛点包括：

- 商品边缘瑕疵
- 背景不协调
- 卖点不突出
- 文字不够吸引人
- 画面比例不符合投放场景
- 整体风格不统一

Web 端修图要解决的是：

**让用户不用重新生成，也不用跳转第三方工具，就能快速把 AI 图修到可发布、可投放、可转化。**

## 平台价值

平台侧核心目标：

1. 提升生成素材可用率
2. 降低二次生成成本
3. 增强电商内容生产粘性
4. 沉淀电商视觉能力

进一步展开：

- `提升生成素材可用率`
  - AI 初稿不完美时，用户可以继续编辑，而不是放弃结果。
- `降低二次生成成本`
  - 局部问题通过涂抹、滤镜、图层、文字等方式修正，减少重复调用生成模型。
- `增强电商内容生产粘性`
  - 从生成工具升级为完整工作流，减少用户外跳到第三方设计工具。
- `沉淀电商视觉能力`
  - 花字样式、滤镜模板、商品构图比例、图层组合都可以逐步平台化、模板化。

## 目标用户

- 电商运营：需要快速修改标题字、卖点标签、尺寸比例和导出
- 设计支持：需要基于 AI 初稿做花字包装、层级整理和细节调整
- 投放人员：需要批量产出不同尺寸的投放素材，并确保主视觉和安全区稳定

## 核心场景

1. 用户导入 AIGC 生成的商品图或图文海报
2. 用户根据投放渠道切换比例和安全区
3. 用户调整主图、文字、装饰元素和层级关系
4. 用户应用基础滤镜和风格化花字
5. 用户撤销/重做、保存草稿并导出最终素材

## MVP 范围

### 推荐 MVP 必做

| 模块 | 功能 |
| --- | --- |
| 画布 | 图片加载、缩放、拖拽、撤销重做 |
| 涂抹 | 笔刷、橡皮擦、局部重绘 |
| 文字 | 添加文字、基础花字模板、描边阴影 |
| 滤镜 | 基础调节、电商滤镜、一键增强 |
| 比例 | 裁剪、固定比例、智能扩图 |
| 图层 | 图层排序、隐藏、删除、锁定 |
| 导出 | 保存草稿、导出图片、回填到图文流程 |

### 二期增强

| 模块 | 功能 |
| --- | --- |
| 智能化 | 智能文案、智能排版、主体保护 |
| 模板化 | 品类模板、活动模板、风格模板 |
| 协同 | 多人审核、版本对比、评论批注 |
| 合规 | 敏感词检测、价格规范、广告法风险提示 |
| 数据化 | 导出率、编辑行为、模板使用率、素材采纳率 |

## 当前版本边界

当前仓库实现的是“推荐 MVP”之前的一版可运行工作台骨架，已经覆盖了比例切换、图层管理、基础花字、基础滤镜、撤销重做、草稿恢复和 PNG/JPEG 导出，但仍未完成涂抹、裁剪、智能扩图、电商滤镜模板和图文流程回填。

最终判断以 [MVP 审计](./mvp-audit.md) 为准。

## 非目标

- 不做 Photoshop 级像素编辑器
- 不做多人实时协同
- 不在当前版本直接承诺复杂 AI 任务编排与审核工作流

## 成功标准

- 用户能在一个工作台内完成 AIGC 初稿的主要二次精修
- 首版高频链路稳定可用：导入 -> 编辑 -> 撤销/重做 -> 保存草稿 -> 导出
- 文档、设计和任务分解以 SDD 方式持续积累，可支撑后续迭代扩展

## 一句话总结

Web 端修图的核心不是做一个“网页版 Photoshop”，而是做一个**面向抖音电商 AIGC 带货图的轻量精修工具**，帮助用户把“不满意的 AI 初稿”快速修成“可发布、可投放、可转化的电商素材”。
